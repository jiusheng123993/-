## 4. AI 分镜脚本生成器（核心新增，§2 的问题 1、2 一起解决）

### 4.1 新增模块：`server/src/services/memoirScriptService.ts`

职责：调用 DeepSeek（`deepseek-v4-flash-ga-260731`）生成结构化分镜，zod 校验，失败重试 2 次（重试换 prompt 兜底模板）。

### 4.2 分镜 JSON Schema（v1）

```jsonc
{
  "title": "豆豆的一生：窗台边的十年",        // 视频标题（字幕开场用）
  "theme": "陪伴与告别",                    // 主题词
  "emotion_curve": ["calm","memory","pain","relief","lingering"], // 情感曲线
  "narration_voice": "晓晓",                // 旁白音色（edge-tts 角色名）
  "music_mood": "nostalgic",                // 全局音乐情绪（映射 BGM 库）
  "identity_anchor": "橘色短毛猫（公），白色胸脯，右耳缺一小角，绿眼睛",  // 身份锚点：全片逐镜逐字重复（Seedance 一致性核心）
  "segments": [
    {
      "photo_index": 0,                     // 对应第几张照片
      "shot_type": "push_in",               // 运镜：push_in/pan_left/tilt_up/zoom_slow/static_drift/dolly_in
      "camera": "close_up",                 // 景别：close_up/medium/wide/over_shoulder
      "lighting": "golden_hour",            // 光线：golden_hour/soft_afternoon/warm_indoor/moonlight
      "transition": "revealing",            // 转场原语：revealing（主体进入）/disappearing（离开）/switching（切换）/cut
      "atmosphere": "安静、温暖、带着思念",    // 氛围描述（仅供脚本理解，不进 prompt——见 Anti-Subjective 规则）
      "duration_sec": 8,                    // 本镜时长（3-8 秒）
      "seedance_prompt": "对这张宠物照片进行缓慢推镜处理……（完整 2.0 提示词，见 §5）",
      "narration": "十年前的那个下午，你第一次跳上窗台。",  // 旁白文案（TTS 用，写视觉细节不写空话）
      "subtitle": "2016 年夏天 · 初遇",       // 字幕（烧录用）
      "music_mood": "warm_piano"            // 本镜音乐情绪（可覆盖全局）
    }
  ]
}
```

> 校验规则：segments 数量 = 照片数（纪念 8-15 / 日常 1-3）；每镜 duration 3-8 秒；总时长落在产品线区间（纪念 60-90 / 日常 5-30）；prompt 长度 80-400 字；**identity_anchor 必须逐镜注入 prompt 且文字一致**（Seedance 对"同一个它"的理解靠逐字重复，代词/简称无效）。

### 4.3 生成 prompt（系统提示词核心）

```
你是一位宠物纪念视频导演兼编剧。根据以下素材，为一个宠物家庭生成一段情感克制的
分镜脚本（禁止煽情过度、禁止虚构不存在的经历，只能基于素材合理延展氛围）。

【宠物档案】品种/性别/年龄/特征
【记忆摘要】AI 记住的宠物喜好/习惯/性格（来自 memory-body）
【用户文案】用户写的回忆文字（如有）
【照片信息】N 张照片，按时间排序（附每张的简短内容描述，如有）
【产品线】纪念Vlog（60-90秒，CREST六段式：背景→铺垫→冲突→留白→释怀→主题）
        或 日常回忆录（5-30秒，温暖片段）

要求：
1. 严格输出 JSON（schema 见下），不要输出任何其他文字
2. **Anti-Subjective 规则（最重要）**：描述"情绪的视觉成因"，禁止用主观情绪词。
   例：不写"氛围温馨感人"，写"黄昏暖光从左侧窗台洒入，猫在光斑里眯眼"；
   不写"悲伤的回忆"，写"空了的猫窝，窗帘被风轻轻吹动"。
   脚本的旁白和 prompt 都必须遵守：每个情绪点都要对应一个看得见的具体画面。
3. identity_anchor：从宠物档案+首张照片提取 3-6 个"能一眼认出它"的物理特征
   （毛色/花纹/体型/五官/特殊标记），写进 JSON 顶部，全片逐镜逐字重复使用。
4. 每镜的 seedance_prompt 用中文，按 8 组件结构组装（见 §5 模板）：
   景别 + 运镜 + 身份锚点 + 动作细节 + 环境 + 光线 + 风格 + 声音氛围，
   其中动作细节只写"从照片能推断"的（如"耳朵在光里透出粉色""尾巴尖轻轻摆动"），
   不编造照片里没有的场景。
5. 旁白文案：口语化、克制、有画面感，每镜 1-2 句话（20-50 字），
   写具体细节（"它总在黄昏蹲在窗台第三块砖上"），避免"永远爱你"式空话。
6. 字幕：短句（≤15 字），可含时间节点（"2018 年冬天 · 第一次下雪"）。
7. 情感曲线遵循 CREST：开头平静留白，中段温暖回忆，转折点到为止（不渲染痛苦），
   结尾释怀与感激。
8. 避免：同镜超过 3 个动作、可读文字/水印、冲突光线（"明亮正午"+"霓虹夜"二选一）。
```

### 4.4 兜底模板

LLM 连续失败 2 次时，用内置模板（从提示词库 §1.1 纪念 Vlog 完整分镜序列抽取）生成基础分镜，保证功能可用（质量降级但不断服）。

### 5.1 Seedance 2.5 Prompt Contract（每镜 prompt 按此十段组装）

> 顺序不能乱：跳段不会整体变差，但会在"可预见的特定方式"上坏掉。

```
GLOBAL STYLE（全局风格·护栏）
  类型/调色/画幅/必须不出现的东西。以下所有段落必须与此一致。
  例：写实风格，柔和暖调，竖屏 9:16；画面中只出现这一只猫，不出现其他动物/人物/文字/水印。

SCENE（一句话剧情线）
  发生什么、在哪、什么氛围。例：橘猫趴在窗台上，黄昏，安静思念。

CHARACTERS（角色）
  面部/毛色/体型。有参考图时只需指明"哪张参考图是哪个角色"。
  例：角色=参考图1（橘色短毛猫，白色胸脯，右耳缺一角）。

LOCATION（位置·防漂移关键）
  空间与道具，与角色分开写。模糊位置是多镜漂移最常见原因。
  例：窗台第三块砖，左侧有绿萝盆栽，玻璃上有旧雨渍。

FIRST FRAME AND BLOCKING（开场构图）
  精确起始位置：谁在哪、朝哪个方向（可用 x/y 百分比）。
  例：猫位于画面 x42%/y55%，头朝右偏 15°，静止趴卧。

Shot 1: [景别][动作，1-2 句]。Hard cut。
Shot 2: [景别][动作，1-2 句]。Hard cut。
  （单镜任务只写一个 Shot；节奏在这里构建，明确镜头距离与构图）

OPTICS/CAMERA（光学）
  焦段（LENS LOCK）、机位高度、手持/轨道。
  例：47° 焦段锁定，机位与猫眼同高，缓慢推镜（dolly-in）。

PHYSICS（物理）
  毛发/胡须/耳朵等易"像固体一样动"的部分。
  例：毛发柔软，随推镜产生的微风轻微浮动；尾巴尖自然摆动，不僵直。

LIGHTING（光线）
  光源动机/方向/如何落在脸上。只选一个光源方案。
  例：黄昏暖光从左窗射入，在猫右侧勾出金边轮廓。

AUDIO（音频·护栏）
  环境声、特效、必须不出现的声音。默认："无音乐、无可辨识对话"。
  例：安静的午后，远处偶有车声；无音乐。
```

> **Prompt 形状总结**：顶部一条视觉规则（GLOBAL STYLE）→ 中间拆成镜头（Shots）→ 底部一条声音规则（AUDIO）。

### 5.2 连续性锁（Locks，解决"多镜拼接后不像同一只猫/场景漂移"）

| Lock | 作用 | 回忆录应用 |
| --- | --- | --- |
| `COUNT LOCK` | 数量锁定："恰好一只，无背景替身，无镜面/倒影出现第二个" | **防多出一只猫/狗**（照片动效高频翻车点） |
| `SCREEN DIRECTION` | 屏幕方向轴："猫始终朝右，永不反转" | 多镜拼接方向一致 |
| `LENS LOCK` | 每镜焦段锁定（84°广角/47°正常/29°人像/18°长焦），"段内无焦段漂移" | 全片画风统一 |
| `STILLNESS LOCK` | "不发生的事"清单：猫保持趴卧不动，只有耳朵/尾巴微动 | 照片动效最实用（防凭空加动作） |
| `FIRST FRAME + BLOCKING` | 开场 x/y 百分比定位 + 反打方向 | 每镜构图稳定 |
| `POSITIVE LOCKS` | 结尾正面复述跨镜保持的事 | 收尾护栏 |
| `IDENTITY / NO-IP LOCK` | 无 logo、无可读文字、无可辨识旋律 | 合规 |
| `State monotonicity` | 状态只前进不倒退（光线只会更暗不会变亮回） | 时间感连续 |
| `One grammar per action` | 重复动作定义一种执行方式，封闭清单 | 动效克制不夸张 |
| `Event tracks` | 环境元素写成带时间戳事件（风在 3s 一次、8s 一次） | 增加真实感 |

> **参考图优势（Seedance 2.5 六大发现之一）**：参考图比文字描述更能跨镜头保持身份一致——回忆录本来就是"真实照片图生视频"，身份一致性天然占优；文字只需补场景/光线/动作。

### 5.3 模板组装示例（纪念 Vlog · 回忆段）

```
GLOBAL STYLE：写实风格，柔和暖调，9:16 竖屏；画面只出现这一只猫，无其他动物/人物/文字/水印。
SCENE：橘猫在黄昏窗台，安静思念。
CHARACTERS：角色=参考图1（橘色短毛猫，白色胸脯，右耳缺一角，绿眼睛）。
LOCATION：窗台第三块砖，左侧绿萝盆栽，玻璃有旧雨渍。
FIRST FRAME：猫在 x42%/y55%，头朝右偏 15°，静止趴卧。
Shot 1（特写，缓慢推镜）：猫趴在窗台，耳朵在光里透出粉色，尾巴尖轻轻摆动。
OPTICS：47° 焦段锁定，机位与猫眼同高，dolly-in。
PHYSICS：毛发柔软随微风浮动；尾巴自然摆动不僵直。
LIGHTING：黄昏暖光从左窗射入，猫右侧勾金边轮廓。
AUDIO：安静午后，远处偶有车声；无音乐。
COUNT LOCK：全片只有这一只橘猫；LENS LOCK：全片 47°。
```

> 对比现在的一句话模板：十段结构 + 锁机制，覆盖"像不像/漂不漂/假不假"三个翻车点。

## 7. BGM 音乐库（替换合成音）

- 来源：**Pixabay 免费可商用音乐**（CC0，无版权风险），按情绪缓存到 `server/uploads/music/`：
  - warm / nostalgic / piano / gentle / bright 各 2-3 首，每首 30-90 秒可循环
- **选曲规范**（OpenMontage Sound Design）：有旁白时必须用**纯音乐（无歌词）**；情绪→BPM 映射（calm/温馨 60-80、怀旧 80-100、温暖钢琴 60-80）；选动态平稳的曲子（避免突然的高潮/鼓点抢戏）
- **混音规范（ffmpeg 参数）**：
  - 旁白：主声，目标 -12 dB 峰值
  - 音乐：说话时压到旁白下方 **18-20 dB**（ducking），音乐音量基础 0.2、旁白出现时自动降到 0.06-0.08（用 ffmpeg `sidechaincompress` 或分段音量）
  - 淡入 2 秒、淡出 2 秒
- 降级：音乐缺失时回退现有合成音（不阻断）

## 8. 后期合成升级（ffmpeg）

| 项 | 现状 | 2.0 |
| --- | --- | --- |
| 转场 | concat 硬切 | **xfade 交叉淡化**（0.5-1 秒），按脚本 transition 原语：revealing/switching 用淡化，pain 段用硬切强化 |

| BGM | 合成音 | 真实音乐（§7） |
| 音频电平 | 无规范 | 旁白 -12 dB / 音乐 duck 18-20 dB / 不失真（§7） |

## 9. 质量质检（新增，DeepSeek 视觉）

- **模型**：`deepseek-v4-flash-vision-exp`（DeepSeek 官方，价格同 flash，成本可忽略）
- **流程**：每镜生成后 ffmpeg 抽 2 帧（首尾）+ 成片抽 3-5 帧 → 批量发视觉模型
- **评分维度**（模型返回 JSON）：画面清晰度（无模糊/花屏）、主体一致性（与原始照片的猫/狗特征一致）、提示词匹配（运镜/光线/氛围是否实现）、明显瑕疵（变形/多腿/乱码）
- **门槛**：任一帧"明显瑕疵"或"主体不一致"→ 该镜重做（重试预算内，见 §10）
- **成本**：每条视频 5-8 帧 ≈ 0.01-0.02 元，可忽略

## 10. 重试与成本预算（防烧钱）

| 层级 | 预算 | 说明 |
| --- | --- | --- |
| 脚本生成 | 2 次 | 失败用兜底模板 |
| 单镜 Seedance | 每镜最多 3 次（现有）→ **全任务总重试 ≤ 5 次** | 超过即任务失败并退款 |
| 质检不过 | 计入单镜重试预算 | 防止无限重做 |
| 整条任务 | 现有 memoirProcessor 最多 2 次 | 保持 |

> 单条纪念 Vlog 成本上限：脚本 0.05 + 12 镜×8 秒×0.15 元/秒×1.3 ≈ 19 元（预算内约 25 元封顶）。

## 11. 数据结构变更

- `memoir_tasks.narrative_structure`（jsonb）：扩展为 `{music_style, duration, style_preset, script: <§4.2 分镜 JSON>}`——**兼容旧数据**（script 缺失时走旧逻辑或兜底模板）
- 新增表 `memoir_scripts`（可选）：`task_id PK, script jsonb, prompt_version text, created_at`——存脚本便于复现/审计/后续素材沉淀
- 存量 pending/processing 任务：迁移时保留（2.0 只对新任务生效）

## 12. 质量验证批次方案（先验证，后上线）

**目标**：3-5 条真实试生成，确认"能卖 99 元"的质量后再正式重做。

| 步骤 | 内容 |
| --- | --- |
| ① 准备素材 | 3 只真实宠物（猫/狗/异宠各 1），各 8-12 张照片 + 一段用户文案（可用测试数据） |
| ② 试生成 | 跑 2.0 管线：纪念 Vlog × 3 + 日常回忆录 × 3 |
| ③ 机器质检 | DeepSeek 视觉抽帧评分（§9），不合格自动重试（预算内） |
| ④ 人工审片 | 你亲自看 6 条成品，对照验收标准打分 |
| ⑤ 验收标准 | 有完整故事线（≥4 镜叙事连贯）/ 画面不假（无翻车帧）/ 旁白自然 / 音乐氛围匹配 / 字幕清晰 |
| ⑥ 决策 | 达标 → 正式重做上线（灰度 20%）；不达标 → 定位是"模型上限"还是"管线问题"，换方案 |

**试生成成本预算**：约 150-200 元（6 条 × 20-30 元 + 重试），一次性验证投入。

## 14. 风险与降级

| 风险 | 降级方案 |
| --- | --- |
| edge-tts 在服务器装不上 | 无旁白但有字幕；或本机生成旁白上传 |
| 中文字体缺失导致字幕乱码 | 跳过字幕并记录日志（视频仍可用） |
| Seedance 单镜反复失败 | 重试预算耗尽 → 任务失败退款（现有机制） |
| 视觉质检误判 | 阈值可调；质检结果仅作为"建议重做"，不硬性阻断（记录指标） |
| 2.0 质量仍不达"可卖"标准 | 验证批次决策点：转 Seedance 2.5（成本 63-84 元/条，定价上调）或收缩为标准模板版 |
