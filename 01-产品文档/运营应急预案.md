## 四、应急流程（按场景操作）

### 1. 服务异常/变慢
1. `pm2 status` 看 `xinghuanhai-server` 状态；`pm2 logs xinghuanhai-server --lines 100`（2026-09 审查修正：生产进程名实为 xinghuanhai-server）
2. 卡死拉起：`pm2 restart xinghuanhai-server`
3. 数据库：`systemctl status postgresql`，`sudo -u postgres pg_isready`
4. 确认恢复：`curl https://<星河宠记域名>/api/health`

### 2. AI 生成不可用（形象/回忆录）
1. 检查各 AI 服务商余额与 Key 状态（DeepSeek / 百炼 / Seedream / Seedance）
2. 看 `err.log` 中对应 adapter 的错误码（429 = 限流，401 = Key 失效，402 = 欠费）
3. 欠费立即充值；Key 失效检查 `.env` 是否被轮换
4. 短期降级：关闭生成入口，保留查询/社区功能

### 3. 支付异常（用户已付款未到账）
1. 查微信支付商户平台订单状态与回调日志（`/api/payment/wechat/notify`）
2. 若回调未到：确认服务器日志里是否有验签失败记录，检查商户密钥是否过期
3. 手动补单：核对订单号后补发会员权益（运营后台操作）
4. 对账：每日跑一次订单对账，自动发现「已支付未到账」

### 4. 磁盘写满（上传图片/视频占空间）
1. `df -h /`，`du -sh /opt/xinghechongji /srv 2>/dev/null | sort -h`
2. 清理过期任务产物（`cleanStaleTasks` 每日自动清理 ✅）、旧日志（`pm2 flush`）
3. 确认上传目录是否有异常膨胀的临时文件

### 5. 内容安全/投诉事件
1. 下架争议内容（图片/记忆/分享卡片）
2. 联系受影响用户说明
3. 把触发词/图片特征加入审核，必要时接微信内容安全接口

### 6. 数据泄露/密钥泄露
1. 轮换全部密钥（`JWT_SECRET`、各 AI Key、数据库密码、支付商户密钥）
2. 查日志定位泄露面；检查备份是否加密
3. 通知用户 + 配合平台/监管

### 7. 上线回滚
1. 保留上一发布版本（Git 打 tag + 服务器保留部署包）
2. `pm2 deploy` 或手动回滚：切回旧版本 `pm2 restart xinghechongji-server`
3. 复盘：先灰度（内测群）再全量
