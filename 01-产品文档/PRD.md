## 一、产品定位

### 一句话描述

**星寰海 — 以memory-body记忆引擎为核心壁垒，先做"有记忆的AI宠物管家"，后做"有记忆的AI职业顾问"，情绪感知作为底层能力融入双场景的微信小程序。**

### 不是什么

| 不是 | 是 |
|------|-----|
| 不是AI宠物医生（诊断） | 是AI宠物健康分诊伙伴（建议是否就医） |
| 不是猎头/职业中介 | 是职业发展工具（技能分析+路径规划） |
| 不是心理咨询平台 | 是情绪感知底层（融入场景的微干预） |
| 不是通用AI聊天机器人 | 是有记忆的垂直场景AI |

### 核心公式

```
memory-body记忆引擎（壁垒）+ 垂直场景知识图谱（专业度）+ 情绪感知底层（差异化）+ 主动触达（留存）
= "有记忆的AI"——市场上不存在的产品形态
```

### 战略路线

```
Phase 1（已完成）：🐾 AI宠物管家 MVP
  ├── 健康打卡/食物查询/症状初筛/疫苗日历/健康趋势
  ├── memory-body 引擎（宠物健康类型）
  └── 验证"有记忆的AI"产品假设 ✅

Phase 1.5（当前→2周）：🐾 宠物 v2.0 — AI深度融合
  ├── AI对话为唯一交互入口（DeepSeek/GLM-4模型）
  ├── 宠物家庭（family/member/lineage）
  ├── 取名引擎（五行+星象+诗词+山川+典故）
  ├── 时光引擎（时间线/回忆录/里程碑/旧时光提醒）
  ├── Guard双守卫（规则+AI语义）
  └── 成本：~90-210元/月

Phase 2（Phase 1.5验证后→3周）：AI深化
  ├── 宠物对话AI成熟（长上下文、意图识别优化）
  ├── 家庭周报AI / 家族图谱 / 全家福合成
  ├── 年度回忆图集
  └── 分享卡片系统

Phase 3（Phase 2验证后）：💼 职业方向 + 交叉导流
  ├── 同一小程序，pagesCareer分包
  ├── 共享基础设施（用户/Auth/支付）
  └── 宠物用户 → 职业顾问导流
```

| 维度 | 所有竞品 | 星寰海记忆引擎 |

### 2.6 替代方案竞争威胁分析

| 替代方案 | 用户为什么用 | 星寰海如何胜出 | 威胁等级 |
|---------|------------|--------------|---------|
| 备忘录/Excel记录宠物健康 | 免费、简单 | 3秒打卡比手动记录更快+AI自动分析 | 低 |
| 通用AI对话（ChatGPT/豆包） | 随时问、免费 | 星寰海有记忆（记住宠物历史）+专业知识库 | 中 |
| 宠物医院纸质记录 | 医生认可 | 数字化+随时查+趋势图+给兽医看 | 低 |
| 宠物医院公众号/小程序 | 权威、信任 | 星寰海不替代医院，是医院前的分诊工具 | 低 |
| 智能硬件（小佩/霍曼） | 自动采集数据 | 星寰海无硬件成本+AI分析+情绪支持 | 中 |
| 通用健康APP（薄荷等） | 习惯养成 | 星寰海垂直宠物场景+专业知识 | 低 |

**最大威胁**：通用AI对话工具（豆包/Kimi/ChatGPT）
- 优势：免费、随时可用、大模型能力强
- 劣势：无记忆、无专业知识库、无主动提醒
- 对冲策略：强调"有记忆"差异化+专业知识库准确度+主动触达留存

### 💼 职业顾问核心用户（Phase 3）

| 画像 | 特征 | 核心需求 | 使用场景 |
|------|------|---------|---------|
| 迷茫期职场人 | 25-30岁，工作2-3年，想转行 | "我该做什么？" | 职业方向诊断、技能差距分析 |

- 需要专业心理咨询/治疗的用户（导流给专业机构）
- 寻找AI虚拟伴侣的用户（监管不允许）

### 4.3 3秒健康打卡（P0 - 核心习惯入口）

#### 4.3.1 打卡设计

```
毛孩子今天怎么样？

便便  [正常] [偏软] [偏硬] [稀便] [血便]
食欲  [正常] [少吃] [多吃] [不吃] [呕吐]
精神  [正常] [兴奋] [安静] [低落] [萎靡]
运动  [正常] [少] [多]

[完成打卡] ← 3秒完成
```

#### 4.3.2 打卡数据写入memory-body

| 打卡项 | 映射到memory-body | 异常阈值 |
|--------|-------------------|---------|
| 便便 | PetHealthEntry.bowel | 血便→立即触发安全机制 |
| 食欲 | PetHealthEntry.appetite | 不吃+呕吐→黄色预警 |
| 精神 | PetHealthEntry.energy | 萎靡→黄色预警 |
| 运动 | PetHealthEntry.exercise | 连续3天少→关注 |
| 体重 | PetHealthEntry.weight | 偏离品种范围±15%→关注 |

#### 4.3.3 打卡后即时反馈

| 打卡结果 | AI反馈 |
|---------|--------|
| 全部正常 | "毛孩子今天状态不错👍" |
| 1项异常 | "注意到[异常项]，继续观察，如果明天还这样告诉我" |
| 2项异常 | "有2个指标不太对，建议关注。如果持续2天建议就医" |
| 3项+异常 | "多个指标异常，建议尽快带毛孩子去医院检查" |
| 血便/不吃+萎靡 | 立即触发红色预警→建议立即就医 |

### 4.4 疫苗驱虫日历（P0 - 高频触点）

#### 4.4.1 自动生成时间表

```
添加宠物后，AI根据品种+年龄自动生成：

🐱 咪咪的疫苗计划
├── 8周：猫三联第1针 ✅
├── 12周：猫三联第2针 ⏳ 7月20日
├── 16周：猫三联第3针
├── 6月龄：狂犬疫苗
└── 之后：每年加强1次

驱虫计划
├── 体内驱虫：每3个月1次
└── 体外驱虫：每月1次（夏季加密）
```

#### 4.4.2 提醒机制

| 提醒时机 | 渠道 | 内容 |
|---------|------|------|
| 到期前7天 | 微信订阅消息 | "咪咪的猫三联第2针还有7天，记得预约" |
| 到期当天 | 微信订阅消息 | "今天该打猫三联第2针了" |
| 逾期3天 | 微信订阅消息 | "咪咪的疫苗已逾期3天，尽快补打" |
| 完成后 | 小程序内 | 记录完成时间，自动计算下次时间 |

### 4.5 AI症状初筛（P1 - 核心差异化）

#### 4.5.1 核心原则

**不是诊断，是分诊。参考海外Petriage模式：用户输入症状→AI评估紧急程度→建议是否就医。**

| 能做 ✅ | 不能做 ❌ |
|---------|---------|
| "检测到异常信号，建议带毛孩子去医院检查" | "你的猫得了肠胃炎"（诊断） |
| 评估紧急程度（绿/黄/红） | 开处方/推荐具体药品 |
| 基于记忆的个性化判断 | 替代兽医诊断 |
| 提供就医前的观察建议 | 告诉用户用什么药 |

#### 4.5.2 症状初筛流程

```
毛孩子怎么了？

Step 1: 选择症状（可多选）
  [呕吐] [腹泻] [不吃] [精神差] [咳嗽] [打喷嚏]
  [皮肤问题] [跛行] [眼鼻分泌物] [排尿异常] [其他]

Step 2: 补充信息
  持续多久了？[今天刚发现/1-2天/3天以上]
  严重程度？[轻微/明显/严重]
  还有其他症状吗？[文本输入]

Step 3: AI综合评估（基于记忆+知识图谱）
  ├── 调取宠物档案：品种、年龄、过敏史、慢性病
  ├── 调取近期打卡：最近7天健康趋势
  ├── 匹配知识图谱：症状→可能原因→紧急程度
  └── 综合判断

Step 4: 输出结果
  ┌──────────────────────────────┐
  │  🟡 建议关注                  │
  │                              │
  │  咪咪（3岁英短）出现了呕吐+   │
  │  精神差的症状，持续1天。      │
  │                              │
  │  结合咪咪的记录：             │
  │  · 上周换粮后便便偏软         │
  │  · 英短肠胃较敏感             │
  │                              │
  │  建议：                       │
  │  1. 先禁食4-6小时观察         │
  │  2. 如果呕吐停止，少量喂食    │
  │  3. 如果明天还呕吐→建议就医   │
  │                              │
  │  ⚠️ 以上建议仅供参考，        │
  │  不替代兽医诊断               │
  │                              │
  │  [记录症状]  [找医院]         │
  └──────────────────────────────┘
```

#### 4.5.3 紧急程度分级

| 等级 | 颜色 | 含义 | 典型症状 | 建议动作 |
|------|------|------|---------|---------|
| 绿色 | 🟢 | 观察 | 单一轻微症状，精神食欲正常 | 继续观察，明天打卡时关注 |
| 黄色 | 🟡 | 关注 | 2个症状或持续1-2天 | 家庭观察+护理建议，持续则就医 |
| 橙色 | 🟠 | 尽快就医 | 多个症状或持续3天+ | 24小时内就医 |
| 红色 | 🔴 | 立即就医 | 血便/抽搐/呼吸困难/误食毒物 | 立即去急诊 |

#### 4.5.4 基于记忆的个性化判断

| 场景 | 无记忆的产品 | 星寰海（有记忆） |
|------|------------|----------------|
| 猫呕吐 | 通用建议："禁食观察" | "咪咪上次换粮后也呕吐了，3天后恢复。这次是换粮吗？如果是，上次禁食6小时后好了" |
| 狗不吃 | 通用建议："观察1天" | "豆豆已经连续2天少吃，上周驱虫后也这样，2天恢复了。但这次精神也差，建议就医" |
| 皮肤问题 | 通用建议："可能过敏" | "咪咪每年春天都皮肤痒，去年用了XX药膏。今年可能又是季节性过敏" |

## 六、情绪底层 — 跨场景能力设计

### 6.1 定位

情绪不是独立模块，是融入宠物/职业场景的**底层感知能力**。用户不会看到"情绪"标签，但会在需要时感受到情绪支持。

### 6.2 情绪底层能力矩阵

| 能力 | 宠物场景 | 职业场景 | 技术实现 |
|------|---------|---------|---------|
| 事前干预 | 宠物手术前焦虑 | 面试/述职前焦虑 | 复用3天拆解干预引擎 |
| 事后急救 | 宠物离世悲伤 | 被拒后低落 | 复用急救箱流程 |
| 主动陪伴 | 宠物生病持续焦虑 | 职业迷茫 | 复用主动触达引擎 |
| 模式发现 | "你每次换粮都焦虑" | "你每次面试都紧张" | 复用模式识别引擎 |

### 6.3 情绪数据采集方式

情绪数据不再独立采集，而是通过场景行为被动采集：

| 场景行为 | 推断情绪 | 采集方式 |
|---------|---------|---------|
| 频繁打开宠物档案 | 焦虑 | 行为信号自动采集 |
| 连续查询食物安全 | 新手焦虑 | 行为信号自动采集 |
| 频繁使用症状初筛 | 担忧 | 行为信号自动采集 |
| 标记宠物"已离世" | 悲伤 | 事件触发 |
| 日历标记面试 | 焦虑 | 事件触发 |
| 面试后标记"未通过" | 低落 | 事件触发 |

### 6.4 情绪底层效果验证标准

| 验证维度 | 指标 | 目标值 | 测量方式 |
|---------|------|--------|---------|
| 触发准确性 | 情绪触发→用户正面反馈率 | >60% | 触发后"有帮助/没帮助"按钮 |
| 干预有效性 | 触发情绪功能后7日留存 vs 未触发 | >未触发组 | A/B对比 |
| 用户满意度 | 情绪功能NPS | >30 | 季度问卷 |
| 安全性 | 极端情绪漏判率 | 0% | 人工抽检+关键词全检 |
| 合规性 | 被判定为心理服务的投诉 | 0 | 客诉监控 |

**验证节奏**：
- MVP期：人工抽检50条/周，调整触发规则
- 成长期：自动统计+月度人工抽检
- 成熟期：全自动化+季度NPS

### 6.5 数据备份与设备迁移方案

| 场景 | 方案 | 实现方式 |
|------|------|---------|
| 日常备份 | 本地优先+云端加密同步 | memory-body引擎自动同步 |
| 换设备 | 新设备登录→云端拉取→本地解密 | Supabase Auth+加密同步 |
| 数据导出 | 设置页"导出我的数据"→生成JSON | 手动触发 |
| 数据删除 | 设置页"删除所有数据"→本地清除+云端删除 | 二次确认+7天冷静期 |
| 账号注销 | 设置页"注销账号"→全部数据删除 | 二次确认+15天保留期 |

**加密细节**：
- 加密层级：私密数据AES-256-GCM加密，密钥由用户密码派生（PBKDF2）
- 密钥管理：密钥不存储在服务端，仅存用户设备Keychain
- 换设备流程：新设备登录→输入密码派生密钥→解密云端数据
- 端到端加密范围：宠物离世悲伤记录、情绪底层记录
- 非加密范围：宠物档案基础信息、健康打卡数据（云端加密足够）

### 14.4 大厂竞争风险对冲方案

| 大厂威胁 | 概率 | 影响 | 对冲策略 |
|---------|------|------|---------|
| 抖音/小红书做宠物健康管理 | 低 | 致命 | 快速积累用户数据→提高切换成本→做本地医院独家合作 |
| 小佩/萌爪加AI记忆 | 中 | 高 | 先发优势+纯软件无硬件门槛+更广品种覆盖 |
| 通用AI（豆包/Kimi）加宠物场景 | 中 | 中 | 垂直知识库准确度>通用AI+主动触达+情绪底层 |
| 腾讯自己做 | 极低 | 致命 | 无法对冲，但腾讯一般不做垂直工具 |

**核心对冲逻辑**：
1. **时间壁垒**：越早积累用户健康数据，切换成本越高
2. **数据壁垒**：用户3个月健康记录=不可迁移的资产
3. **渠道壁垒**：本地宠物医院独家合作→线下流量入口
4. **体验壁垒**：情绪底层=竞品短期无法复制的差异化
5. **成本壁垒**：规则引擎0成本→竞品用AI→竞品用大模型成本高

**如果大厂跟进的应对**：
- 阶段1（0-6个月）：快速获客+积累数据，建立时间壁垒
- 阶段2（6-12个月）：做深本地医院合作，建立渠道壁垒
- 阶段3（12个月+）：如果大厂碾压，考虑被收购或转型B端SaaS

- 直接反映产品核心价值（持续追踪宠物健康）
- 可衡量、可追踪、可驱动
- 与留存、付费强相关

### 16.2 核心指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| 7日留存率 | 首次使用后第7天仍活跃 | >20% |
| 30日留存率 | 首次使用后第30天仍活跃 | >12% |
| 打卡完成率 | 添加宠物→连续7天打卡 | >40% |
| 食物查询率 | 活跃用户中查询食物安全比例 | >30% |
| 症状初筛率 | 活跃用户中使用症状初筛比例 | >10% |
| 付费转化率 | 付费用户/总注册用户 | >3% |
| 分享率 | 分享次数/活跃用户 | >5% |

### 16.3 埋点方案

| 指标 | 埋点事件名 | 上报时机 | 参数 | 对应核心指标 |

## 附录：核心壁垒总结

| 壁垒 | 说明 | 竞品能否复制 |
|------|------|-------------|
| memory-body引擎 | 长期健康记忆，AI建议基于完整历史 | 难，需从零构建5层架构 |
| 健康数据积累 | 用户使用越久数据越丰富，切换成本越高 | 难，时间壁垒 |
| 宠物医学知识图谱 | 200+常见病+500+食物安全+250+品种 | 中等，数据源公开但需结构化 |
| 情绪底层 | 场景化情绪支持，竞品完全空白 | 难，需memory-body支撑 |
| 主动触达 | 疫苗/驱虫/异常提醒，竞品无此能力 | 中等，需记忆引擎支撑 |
| 双模块协同 | 宠物+职业交叉导流 | 难，需两个模块都做好 |
