## 一、产品定义

### 一句话

> 星河宠记宠物 = 一个以 AI 对话为唯一交互入口、宠物时间线为主视角、健康管理与回忆记录为数据底盘、家庭关系为组织维度的**宠物全生命周期数字伴侣**。

### 核心理念（四字）

| 关键词 | 含义 |
|--------|------|
| **时** | **时间线**是产品主视角。所有数据（打卡、照片、疫苗、生病、取名、新生）按时间展示。 |
| **聊** | **AI对话**是唯一交互层。用户不找"功能"，和AI聊就够。 |
| **记** | **健康数据+回忆记录**是底盘。结构化数据自动沉淀，用户主动发的情感内容另行保存。 |
| **家** | **家庭**是组织维度。多宠不是散装管理，而是一家人。 |

### 与竞品的差距（AI 拉满后）

| 维度 | 所有竞品 | 星河宠记 v2.0 |
|------|---------|------------|
| AI问诊 | 无状态，每次从零开始 | 有记忆：完整档案+半年打卡+时间线 |
| 取名 | 无 | 五行+星象+诗词+山川+典故全方位解读 |
| 记录 | 纯人工 | AI辅助：照片自动描述+旧时光重建 |
| 多宠 | 列表 | 家庭：族谱+看板+周报+合影 |
| 对话 | 不存在 | 核心壁垒：聊宠物，AI记得全部历史 |

## 二、架构设计

### 2.1 小程序分包方案（与职业方向的关系）

```
主包（<700KB）：
├── 入口页（宠物 / 职业 双入口）
├── 登录 / Auth
├── 公共组件 + 公共工具
└── 公共 Store

pagesPet 分包（宠物方向，<2MB）：
├── AI对话主页
├── 时间线视图
├── 家族图谱
├── 健康面板
├── 家庭看板
└── 宠物档案

pagesCareer 分包（职业方向，Phase 3，当前不开发）
```

**职业方向的关系**：Phase 3 再开发职业方向。宠物+职业共享：用户表、Auth、设置。各方向数据独立，通过 user_id 关联。

### 2.2 系统架构

```
用户
 │
 └──→ 🗣️ AI对话层（唯一用户交互入口）
      │
      ├── 意图识别（打卡/取名/咨询/记录/提醒/闲聊）
      ├── AI Guard（规则 + AI语义双守卫）
      │   ├── 规则层Guard：关键词+正则，0成本
      │   └── AI层Guard：语义检测，~0.0005元/次
      │
      ├── 分发到引擎层：
      │   ├── 健康引擎 → 打卡/症状/疫苗/喂养/趋势
      │   ├── 时光引擎 → 回忆帖/里程碑/时间线/旧时光
      │   ├── 家庭引擎 → 家庭CRUD/族谱/看板/周报
      │   ├── 取名引擎 → 解读/推荐
      │   └── memory-body → 存储/同步/安全/加密
      │
      └── 页面级视图（AI对话之外可直接切换）
          ├── 📜 时间线视图
          ├── 📊 健康面板
          ├── 🧬 家族图谱
          ├── 📅 家庭日历
          └── ⚙️ 宠物档案
```

### 2.3 关键设计决定

1. **AI对话是入口，不是功能。** 用户不找打卡、不找取名、不找时间线——只和AI聊天，AI分发给底层模块。
2. **底层模块对用户透明。** 打卡背后是健康引擎，取名背后是取名引擎，用户永远不需要关心。
3. **健康数据自动沉淀。** 打卡→结构化存储→趋势分析→异常预警，全自动。
4. **回忆内容用户主导。** 用户决定什么值得记录，不和打卡数据混在一起。
5. **家庭是多宠统一维度。** 看板+时间线+日历+相册四合一。

## 三、功能模块详细设计

### 3.1 🗣️ AI 对话层

**定位**：唯一用户交互入口。取代传统功能菜单导航。

**能力矩阵**：

| 用户意图 | AI处理方式 | 底层引擎 |
|---------|-----------|---------|
| "给青橘打卡" | 引导5项选择→写入打卡记录→生成动态卡片 | 健康引擎 + 时光引擎 |
| "青橘最近食欲不好" | 调取近14天打卡+症状记录→AI分析→建议 | 健康引擎 |
| "给小猫取名" | 提供取名两种模式 → AI生成推荐/解读 | 取名引擎 |
| "帮我记住今天" | 引导上传照片+描述 → 写入时间线 | 时光引擎 |
| "看看青橘的一生" | 展示时间线视图（打卡+照片+里程碑） | 时光引擎 |
| "今天大家都在干啥" | 展示家庭看板+本周摘要 | 家庭引擎 |
| "青橘不对劲" | 引导症状初筛流程 → Guard → AI分析 | 健康引擎 |
| "青橘走了" | Guard检测悲伤→安全干预→陪伴对话 | 时光引擎 + Guard |

**AI 模型选择**：

| 能力 | 模型 | 月成本 |
|------|------|--------|
| 宠物对话 / 取名解读 | DeepSeek-v3 / GLM-4 | ~50元 |
| 照片描述 | GLM-4v 等多模态 | 含在上项 |
| Guard 语义检测 | 轻量分类模型 | ~10元 |
| 种子图片生成 | Seedream API | ~30-150元 |
| **总计** | | **~90-210元/月** |

**AI Prompt 结构**：
```
System Prompt 注入内容：
1. 角色定义：星河宠记AI宠物管家
2. 当前上下文：
   ├── 用户基础信息
   ├── 当前活跃宠物完整档案
   ├── 近14天打卡记录
   ├── 时间线精华事件
   ├── 家庭信息
   └── 品种知识图谱片段
3. 安全约束规则
4. 输出风格：温暖、精准、简洁
```

### 3.2 🛡️ Guard 双守卫

**第一层：规则 Guard（0成本，高吞吐）**
- P0关键词阻断：毒品/自杀/虐待动物
- 宠物安全规则：有毒物质500+匹配
- 隐私泄露防护：手机号/身份证正则
- 输出清洗：<100字符限制，防止堆栈泄露

**第二层：AI Guard（~0.0005元/次）**
- 输入前：分类模型判断是否有害意图（0-10）
- 输出后：检查AI回答是否包含不安全医疗建议
- 情绪检测：用户是否处于危机状态

**危机响应协议**：
```
检测到情绪危机
  ├── 极危（自伤/自杀）→ 阻断AI + 危机弹窗（不可关闭）+ 热线
  └── 中等 → 不阻断，AI回答中加入温暖验证 + 热线引导
```

### 3.3 📊 健康引擎（数据向·自动沉淀）

| 功能 | 说明 | AI能力 |
|------|------|--------|
| 日常打卡 | 便便/食欲/精神/运动/体重 | AI即时反馈 |
| 症状初筛 | 4步流程→绿/黄/橙/红 | AI诊断参考+规则引擎 |
| 疫苗/驱虫 | 自动排期+到期提醒 | 规则引擎 |
| 就医/用药 | 手动记录诊断+用药+医嘱 | 关联打卡变化 |
| 恢复追踪 | 病后AI跟进闭环 | AI状态检测 |
| 喂养建议 | 品种+年龄+健康+季节 | AI综合推荐 |
| 模式发现 | 发现隐藏规律（如换粮后症状） | memory-body+AI |
| 早期预警 | 对比历史趋势，提前发现异常 | AI趋势对比 |
| 健康趋势图 | 图表展示+异常标记 | 规则引擎+AI分析 |

### 3.4 📖 时光引擎（内容向·用户主导）

| 功能 | 说明 | AI能力 |
|------|------|--------|
| 回忆帖 | 照片+文字记录 | AI自动生成描述文案 |
| 里程碑 | 自动标记（到家/生日/疫苗） | 规则引擎 |
| 时间线 | 按天展示所有事件（纯回忆，不含打卡） | AI排序+摘要 |
| 旧时光提醒 | "去年的今天……" | AI避伤心+智能选择 |
| 年度回忆 | Phase 2 AI选片+配乐（先做图文版） | AI编排 |

**关键原则**：回忆录不混入日常打卡数据。打卡数据有独立的健康面板。

### 3.5 🏠 家庭引擎（关系向·多宠统一）

| 功能 | 说明 | AI能力 |
|------|------|--------|
| 创建家庭 | 取名（五行/星宿/诗词） | AI取名推荐 |
| 成员管理 | 多宠归入家庭 | - |
| 繁衍关系 | 记录谁生了谁 | AI自动生成家族图谱 |
| 族谱树 | 可视化血缘+非血缘关系 | AI图谱生成 |
| 健康看板 | 一页看所有成员健康摘要 | - |
| 家庭日历 | 合并所有提醒+智能排序 | AI紧急排序 |
| 家庭相册 | 所有成员的共享照片墙 | AI面孔识别(Phase 2+) |
| 家庭动态墙 | 自动+手动记录日常 | AI周报生成 |
| 排行+角色 | 老大/团宠/星宿标签 | - |
| 家庭徽章/合影 | 自动生成+AI合成 | AI合成 |
| 多宠分析 | "最近两只互动少了" | AI行为发现(Phase 2+) |

**关键原则**：家庭是概念层，不是存数据的地方。数据仍在宠物档案/健康表里，家庭做聚合展示。

### 3.6 🏷️ 取名引擎（工具向·嵌入流程）

| 模式 | 说明 |
|------|------|
| 用户有想法 | 输入名字→AI从五行/星象/诗词/典故分析解读 |
| 用户没想法 | 品种+出生日期+季节→AI推荐3-5个名字 |
| 嵌入场景 | 添加宠物/新生宠物/独立入口 |
| 数据源 | 五行八卦、二十八星宿、古诗词/楚辞/诗经、山川地名、文化典故 |

## 六、AI Guard 详细设计

### 6.1 规则 Guard（关键词层）

```typescript
interface RuleGuard {
  // P0: 生命威胁
  SELF_HARM_KEYWORDS: string[]    // 自杀、自伤
  ANIMAL_ABUSE_KEYWORDS: string[] // 虐待动物、毒杀宠物
  
  // P1: 隐私泄露
  PRIVACY_PATTERNS: RegExp[]      // 手机号、身份证、银行卡
  
  // 宠物安全
  TOXIC_FOOD_NAMES: string[]      // 500+ 有毒食物名
  
  // 输出清洗
  MAX_OUTPUT_LENGTH: 100          // 错误信息截断
}
```

### 6.2 AI Guard（语义层）

```typescript
interface AiGuard {
  // 输入检测
  checkInput(text: string): Promise<{
    isHarmful: boolean      // 有害意图 0-10
    isCrisis: boolean       // 情绪危机
    action: 'pass' | 'block' | 'crisis_intervention'
  }>

  // 输出检测  
  checkOutput(text: string): Promise<{
    isUnsafeMedicalAdvice: boolean
    needsRegeneration: boolean
    reason?: string
  }>
}
```

**危机响应流程**：
```
检测到危机(score > 7)
  ↓
规则Guard判断严重程度
  ├── 极危(自杀/自伤) → 阻断AI → 危机弹窗(不可关闭)
  │   └── 弹窗内容：热线 + "你需要帮助吗？"
  └── 中等(悲伤/焦虑) → 不阻断 → AI回答加温暖验证
      └── "你需要找个人聊聊吗？这边有个热线……"
```
