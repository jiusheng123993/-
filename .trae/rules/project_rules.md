# 星寰海 项目规则

> 本文件为项目特定规则。全局规则（会话开始、CodeGraph、Git、测试、开发流程、交付审计）已在全局 User Rules 中定义，Agent 必须同时遵守全局规则和本项目规则。

## 1. 项目特定会话开始（在全局规则基础上追加）

### 1.1 读取核心文档
- 读取 `docs/PRD.md` 了解产品定位
- 读取 `docs/TECH_DESIGN.md` 了解技术方案

### 1.2 输出接手摘要
- 当前进度（哪个阶段、哪些模块完成）
- 下一步要做什么
- 是否有阻塞问题

---

## 2. 任务状态追踪（每次修改代码后自动更新）

### 2.1 任务清单
所有开发任务的状态必须写入项目记忆，状态包括：
- ⏳ 未开始
- 🔄 进行中
- ✅ 已完成
- ❌ 已取消
- 🚫 阻塞

### 2.2 每次代码修改后
- 更新对应任务状态
- 写入项目记忆（remember_project_context，type=decision）

### 2.3 每次会话结束前
- 写入 handoff 记录（record_handoff_note）
- 包含：当前进度、下一步、阻塞问题

---

## 3. 并行开发规则

### 3.1 模块锁定机制（多窗口开发支持）
- 锁文件目录：`.trae/locks/`
- 开发前必须先检查锁状态，确认目标模块未被锁定
- 锁定模块：创建 `{模块名}.lock` 文件，status 设为 `locked`
- 释放模块：删除锁文件或更新 status 为 `completed`
- 锁超时：默认 2 小时，超时后其他会话可强制覆盖
- 详细规则见全局规则 rule-02-memory.md 第 10.15 节

### 3.2 禁止重复开发
- 开发任何模块前，必须先检查任务清单确认该模块状态
- 如果状态是"已完成"或"进行中"，禁止重复开发
- 如果状态是"进行中"，先检查 Git 改动确认进度

### 3.3 模块隔离
- 每个模块独立目录，互不依赖
- 修改一个模块时，不得同时修改其他模块
- 一个模块完成并验证后，再开始下一个

---

## 4. 开发流程

### 4.1 编码前
1. 确认任务状态（从项目记忆读取）
2. 确认模块没有被其他人开发（检查 Git 状态）
3. 更新任务状态为"进行中"

### 4.2 编码中
1. 只修改当前模块的文件
2. 每完成一个子功能，运行测试验证
3. 不跨模块修改

### 4.3 编码后
1. 运行 lint + typecheck + test
2. 更新任务状态为"已完成"
3. 写入项目记忆
4. 输出交付摘要

---

## 5. 文档优先

- 所有开发必须对照 `docs/PRD.md` 和 `docs/TECH_DESIGN.md`
- 如果发现文档和代码不一致，先更新文档再改代码
- 新增功能必须先更新 PRD
