## 五、风险与注意事项

### 5.1 技术风险

| 风险 | 影响阶段 | 对策 |
|------|----------|------|
| Three.js 包体过大 | P4 | 按需加载，移动端降级2D |
| ReadyPlayerMe 国内访问慢 | P4 | 备选 Meshy AI 或自建捏脸 |
| WebSocket 长连接稳定性 | P3 | 心跳检测 + 自动重连 + 指数退避 |
| 支付商户号申请周期 | P3 | 提前申请，先用模拟环境开发 |
| Capacitor Android 构建失败 | P5 | 先验证构建流程，确保 Gradle/Android SDK 配置正确 |
| 移动端性能不足 | P5 | 懒加载、虚拟列表、图片压缩、Web Worker 离线计算 |
| 移动端 UI 适配遗漏 | P5 | 逐页面检查 360px-428px 宽度，建立移动端测试清单 |

### 5.2 架构风险

| 风险 | 对策 |
|------|------|
| Persona 两套体系并存导致混乱 | 阶段0必须解决，选择一套统一 |
| localStorage 数据迁移到服务端 | 设计迁移脚本，保留本地兜底 |
| 模块间耦合加深 | 每个模块独立目录，通过 Provider/Adapter 解耦 |

### 5.3 资源风险

| 风险 | 对策 |
|------|------|
| AI API 调用成本 | 规则引擎兜底，批量定时任务，缓存策略 |
| 3D 资产制作成本 | 优先使用 ReadyPlayerMe/Meshy AI 生成 |
| 测试覆盖不足 | 每个模块必须包含测试文件 |
