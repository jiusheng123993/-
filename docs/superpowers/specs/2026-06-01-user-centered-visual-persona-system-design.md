# 用户场景驱动的视觉主题与功能模块系统设计

## 1. 背景

当前项目已经从单一“个人学习规划记录”扩展为“个人效率、学习、办公、成长与生活管理工作台”。用户明确反馈：现有配色不能只凭感觉，必须基于视觉舒适度、美术配色原则和真实用户使用习惯重新设计；功能也不能所有人都一样，应面向不同用户的真实生活、学习、办公和身体状态场景进行差异化设计。

本设计用于替代早期只面向学习场景的设计方向，作为后续主题系统、Persona 场景、功能模块、壁纸上传、女性周期/能量管理、隐私分级和后续 AI 能力的统一产品规格。

## 2. 调研结论

### 2.1 视觉舒适度

- 长时间使用的效率工具应以中性色、低饱和色和清晰层级为基础。
- 高饱和色可以提升情绪价值，但不适合大面积铺满，应作为按钮、徽章、重点状态和激励反馈使用。
- 正文与背景需要满足可读性要求，普通正文对比度目标不低于 4.5:1，标题、图标和大字号文本目标不低于 3:1。
- 颜色不能作为唯一语义表达方式，状态必须同时提供文字、图标或标签。
- 深色模式不能简单反色，应避免纯黑背景和纯白正文造成眩光。
- 视觉系统建议采用 60/30/10 或 70/20/10 配色比例：大面积中性底色，小面积辅助色，少量强调色。

### 2.2 多巴胺配色

- 多巴胺配色适合年轻用户、打卡激励、成就系统和情绪价值场景。
- 纯高饱和撞色容易造成视觉疲劳，第一版应采用“轻多巴胺”或“奶油多巴胺”：奶油底色、柔雾色、低饱和中性色作为主背景，高亮色仅用于 10% 左右的视觉点缀。
- 多巴胺不应作为唯一默认风格，应与极简、高级、国风、水墨、商务和夜间主题并列。

### 2.3 中国风、水墨与新中式

- 水墨和新中式需要拆分为两个主题方向。
- 水墨留白强调淡墨层次、纸感、留白、静心、低刺激，适合复盘、阅读、深度学习和安静办公。
- 新中式国风强调传统色、青绿、朱砂、米白、墨色、窗棂、山水等文化符号，但必须避免符号堆砌。
- 两者都必须服从现代 UI 可读性和交互效率，不应做成“古风网页”。

### 2.4 二次元与治愈风格

- 二次元用户更重视陪伴感、梦幻感、角色感、柔和动效和情绪治愈。
- 角色、贴纸、插画、装饰必须可关闭，不能遮挡任务信息。
- 二次元主题适合创作者、自律恢复、轻量记录、灵感管理和情绪陪伴，不宜强加给职场严肃场景。

### 2.5 女性周期与健康管理

- 女性周期管理需求包括经期开始/结束记录、周期预测、排卵/易孕期提示、经量、痛经、症状、情绪、睡眠、运动、饮食、能量波动和提醒。
- 该模块属于高敏感隐私数据，第一版必须本地优先，不默认上传，不默认同步。
- 该模块只能做记录、提醒、趋势和生活建议，不能给医学诊断结论。
- 需要提供隐私锁、数据导出、删除入口和医学免责声明。

### 2.6 效率工具痛点

- 用户放弃效率工具的常见原因包括同步复杂、功能分散、缺乏专注机制、任务来源太碎、优先级混乱、计划与执行脱节、复盘成本过高。
- 普通待办只能记录“要做什么”，但无法解决“现在先做什么”“为什么没做完”“下一步怎么恢复”的问题。
- 产品需要从用户压力时刻出发，而不是从功能清单出发。

## 3. 产品定位

产品定位调整为：

“以用户真实场景驱动的个人效率与成长工作台。”

它不是单纯学习 App，也不是普通办公 App，而是通过可组合的主题、场景模板和功能模块，适配学习、办公、创作、自律、健康节律和生活目标管理。

## 4. 核心设计原则

### 4.1 先场景，后功能

每个功能必须回答：用户在真实生活或办公中的哪个痛点时刻需要它。

### 4.2 主题与功能解耦

用户喜欢极简、二次元、国风、水墨、多巴胺或商务风，不等于他的功能需求也相同。视觉主题、用户场景和功能模块必须拆开。

### 4.3 首页按场景变化

不同 Persona 的首页重点不同：

- 学生：薄弱点、错题、复习队列、考试倒计时。
- 职场：会议行动项、负责人、DDL、阻塞风险、周报素材。
- 创作者：灵感箱、选题孵化、发布日历、客户交付。
- 自律成长：低压力习惯、能量曲线、断后恢复、温柔复盘。
- 女性周期：周期预测、今日能量、症状记录、低压力任务建议。
- 生活管理：健身、财务、职业成长、作息恢复等模块化入口。

### 4.4 功能按模块开启

不能按性别刻板绑定功能。女性也可能需要项目管理，男性也可能需要情绪记录。系统应允许用户开启需要的模块，而不是强制预设。

### 4.5 低压力设计

应用不能只会催促。用户状态差、计划中断或身体不舒服时，应提供低能量模式、最小行动建议和恢复入口。

### 4.6 隐私分级

普通任务、健康数据、情绪记录、财务目标、壁纸和 AI 输入应使用不同隐私级别。敏感数据默认本地优先，云同步需单独授权。

## 5. 系统分层

### 5.1 Theme Profile

负责官方主题套装，包括颜色、渐变、文字色、卡片色、阴影、圆角、动效强度、插画风格和推荐场景。

### 5.2 Wallpaper Layer

负责用户自定义壁纸和壁纸可读性保护，包括本地上传、遮罩、模糊、亮度、饱和度、暗角和隐私保存策略。

### 5.3 Persona Template

负责不同用户场景的默认工作流，包括首页结构、模块顺序、推荐指标、默认行动和复盘问题。

### 5.4 Feature Module

负责可开关能力，例如错题复盘、会议行动项、灵感箱、女性周期、健身计划、财务目标、专注计时、AI 总结等。

### 5.5 Privacy Level

负责数据敏感级别、存储策略、同步策略、导出删除和日志脱敏规则。

## 6. 第一阶段主题范围

第一阶段提供 8 个官方主题。

### 6.1 极简高级感

- 定位：长期使用、低噪音、高级、耐看。
- 推荐用户：大多数用户、办公、学习、长期计划。
- 视觉：米白、灰蓝、雾绿、木色、深灰文字。
- 角色：默认候选 1。

### 6.2 轻多巴胺年轻感

- 定位：快乐、打卡、成长、情绪激励。
- 推荐用户：年轻用户、自律打卡、轻松成长。
- 视觉：奶油底色、柔雾粉、浅黄、薄荷绿、小面积高亮。
- 角色：默认候选 2。

### 6.3 水墨留白

- 定位：安静、淡雅、东方、静心。
- 推荐用户：阅读、复盘、深度学习、晚间整理。
- 视觉：宣纸米白、淡墨、松烟黑、灰绿、留白。
- 角色：中国审美中偏安静的一支。

### 6.4 新中式国风

- 定位：文化感、仪式感、传统色。
- 推荐用户：喜欢国风、传统文化、沉稳审美的人。
- 视觉：米白、青绿、朱砂、墨色、宫墙红、窗棂/山水元素。
- 角色：中国审美中偏装饰和文化表达的一支。

### 6.5 二次元治愈

- 定位：梦幻、陪伴、治愈、ACG。
- 推荐用户：ACG 用户、创作者、自律恢复用户。
- 视觉：樱粉、天青、电光紫、奶油白、柔和渐变。
- 约束：角色、贴纸和装饰必须可关闭。

### 6.6 莫兰迪温柔

- 定位：低饱和、柔和、生活记录、不焦虑。
- 推荐用户：生活管理、女性成长、自律恢复、低刺激偏好用户。
- 视觉：灰粉、灰蓝、豆绿、暖米色、低对比柔和卡片。

### 6.7 商务蓝灰

- 定位：专业、效率、项目推进。
- 推荐用户：职场、项目管理、会议、周报。
- 视觉：蓝灰、冷白、深蓝、少量金色或橙色强调。

### 6.8 夜间专注

- 定位：低眩光、深夜、专注、写作。
- 推荐用户：夜间学习、写作、低光环境用户。
- 视觉：深蓝灰、非纯黑背景、柔和浅蓝/薄荷绿强调。

## 7. 默认主题策略

默认主题不唯一。首次进入应用时提供“默认体验选择”：

1. 极简高级感：推荐给长期使用和办公学习用户。
2. 轻多巴胺年轻感：推荐给希望更有激励感的用户。
3. 水墨留白：推荐给喜欢安静东方审美的用户。
4. 商务蓝灰：推荐给职场办公用户。
5. 夜间专注：推荐给夜间使用较多的用户。

用户可随时在主题中心切换。

## 8. 壁纸上传设计

### 8.1 功能范围

- 支持用户上传本地图片作为桌面背景或应用背景。
- 支持预览、替换、删除和恢复默认背景。
- 壁纸默认仅本地保存。

### 8.2 可读性保护

上传壁纸后，系统必须提供：

- 遮罩强度调节。
- 背景模糊调节。
- 亮度调节。
- 饱和度调节。
- 暗角保护。
- 卡片背景透明度调节。
- 文字可读性预警。

### 8.3 隐私约束

- 壁纸可能包含私人照片，不得默认上传云端。
- 截图、日志和错误报告不得自动包含壁纸原图。
- 后续如支持同步，必须由用户单独开启。

## 9. 用户场景设计

### 9.1 学生/备考

真实场景：白天上课，晚上刷题，临近考试时资料很多、错题很多、计划频繁变化。

核心问题：用户不知道今天先学什么最能提分。

需要功能：

- 科目进度。
- 薄弱点优先级。
- 错题复盘。
- 间隔复习。
- 模考倒计时。
- 今日冲刺。
- 学习专注计时。
- 复盘问题：今天哪个知识点最容易忘，明天怎么复习。

首页重点：薄弱科目、到期复习、错题难度、今日主线。

### 9.2 职场/办公

真实场景：上午开会，下午改方案，晚上补行动项和周报，任务来自会议、聊天、文档和口头沟通。

核心问题：责任人、截止时间、阻塞点和背景信息散落。

需要功能：

- 项目看板。
- 会议行动项。
- 负责人。
- DDL。
- 阻塞风险。
- 周报素材池。
- 时间盒。
- 会议纪要/待办整理。

首页重点：今日交付、待确认事项、风险、周报素材。

### 9.3 内容创作者

真实场景：灵感来得快也丢得快，个人内容、客户需求和发布计划混在一起。

核心问题：缺少从灵感到发布的生产线。

需要功能：

- 灵感箱。
- 选题孵化。
- 大纲/草稿。
- 发布日历。
- 素材库。
- 客户交付。
- 内容数据复盘。

首页重点：待孵化灵感、进行中内容、发布时间、客户交付。

### 9.4 自律成长

真实场景：用户不是不想变好，而是一断打卡就觉得前功尽弃。

核心问题：连续打卡容易制造焦虑，断后需要恢复入口。

需要功能：

- 低压力习惯。
- 最小行动。
- 断后恢复。
- 能量曲线。
- 温柔复盘。
- 成就奖励。
- 非惩罚式提醒。

首页重点：今天最小行动、能量状态、恢复建议、轻复盘。

### 9.5 女性周期/能量管理

真实场景：经前、经期、痛经、睡眠和情绪波动会影响学习、办公和自律计划。

核心问题：普通计划系统不理解身体状态，容易让用户把状态波动误解为失败。

需要功能：

- 经期开始/结束记录。
- 周期预测。
- 排卵/易孕期提示。
- 经量记录。
- 痛经等级。
- 症状记录。
- 情绪记录。
- 睡眠/运动/饮食关联。
- 今日能量建议。
- 经期前提醒。
- 隐私锁。
- 本地数据导出/删除。

首页重点：周期阶段、今日能量、建议任务强度、症状快捷记录。

安全边界：不做医学诊断，不提供治疗承诺，异常情况只提示就医建议。

### 9.6 生活管理/其他需求

真实场景：用户可能关心健身、财务、职业成长、作息恢复、长期目标，也可能只想轻量记录。

核心问题：不能用性别决定功能，必须按需求模块开启。

需要功能：

- 健身计划。
- 财务目标。
- 职业成长。
- 作息恢复。
- 阅读计划。
- 轻量日记。
- 长期目标里程碑。

首页重点：用户开启什么模块，就显示对应关键指标和今日行动。

## 11. 数据与隐私等级

### 11.1 普通数据

任务、目标、普通笔记、主题选择。

默认策略：本地保存，可在后续同步中默认纳入。

### 11.2 私人数据

壁纸、情绪记录、生活日志、周报素材。

默认策略：本地保存，云同步需提示。

### 11.3 高敏感数据

女性周期、健康症状、财务目标、AI 输入中的隐私文本。

默认策略：本地优先，不默认同步；同步、导出、备份必须单独授权。

## 12. 架构影响

现有代码已经有主题注册表、Persona 模板和本地存储基础。后续应按以下方向扩展：

- 将主题注册表升级为 Theme Profile Registry。
- 增加 Wallpaper Layer 配置和本地存储。
- 将 Persona Template 与 Feature Module 解耦。
- 将 StudyState 逐步演进为 WorkspaceState，避免只围绕学习命名。
- 增加 PrivacyLevel 类型，给不同数据模块标记隐私等级。
- 女性周期模块应作为独立 Feature Module，不直接混入普通任务模块。

## 12.5 小程序完整移动版设计

### 12.5.1 定位

小程序端纳入正式产品形态，定位为“可独立使用的完整移动版应用”，而不是桌面端的简单遥控器。桌面端负责深度规划、长文复盘、模块配置和长期数据管理；小程序端负责移动场景下的计划执行、快速记录、专注打卡、状态查看、轻量复盘和模块入口。

### 12.5.2 产品边界

小程序第一版采用“完整但模块化”的策略：核心闭环完整，复杂能力通过模块开关逐步开放。

第一版默认包含：

- 首页工作台：今日任务、优先级、打卡、能量状态和快捷入口。
- 计划 / 任务 / 日程：支持学习、办公和生活目标，包含优先级、截止时间和轻量复盘。
- 快速新增：支持任务、灵感、症状、笔记、错题和临时想法的快速记录。
- 专注与打卡：支持番茄专注、习惯打卡、连续记录和低压力恢复。
- 统计复盘：提供今日完成、专注时长、打卡趋势和模块关键指标。
- 模块中心：学生、职场、创作、女性周期、健身、财务等模块按需开启。
- 主题中心：复用 Theme Profile，但移动端减少复杂动效和大面积装饰。
- 我的：隐私设置、本地导出、删除、同步预留和账号入口。

### 12.5.3 页面结构

小程序底部导航建议为五个主入口：

1. 首页：展示今日最重要事项、打卡、状态提醒和快捷入口。
2. 计划：管理任务、日程、目标、优先级和复盘。
3. 快速新增：作为中间主操作入口，降低记录成本。
4. 模块：管理学习、办公、创作、健康、财务和生活模块。
5. 我的：管理主题、隐私、同步、导出和设置。

### 12.5.4 数据与同步

小程序端与桌面端共享统一 WorkspaceState 概念，但实现上需要通过平台适配层隔离存储差异。桌面端可继续使用本地存储、Electron 文件存储或后续 SQLite；小程序端使用小程序本地存储和后续云同步 Provider。同步能力第一版只做数据契约和接口预留，不强制上线真实云同步。

高敏感数据仍遵循隐私分级：女性周期、健康症状、财务目标和 AI 隐私输入默认本地优先，不默认同步；若未来支持同步，必须单独授权，并提供导出和删除入口。

### 12.5.5 技术实现建议

小程序端不应直接复用 React DOM 组件，应复用更底层的业务契约：Theme Profile、Persona Template、Feature Module、PrivacyLevel、WorkspaceState 数据结构和 Provider 接口。UI 层按小程序原生组件或跨端框架单独实现，避免桌面端 UI 与小程序 UI 相互污染。

如果后续选择跨端框架，优先评估 Taro 或 uni-app；如果目标是微信生态内体验优先，则可以先用微信小程序原生实现。无论选择哪种方式，都必须保持数据模型、模块开关、隐私等级和主题 token 与桌面端一致。

## 13. 风险与边界

### 13.1 视觉风险

- 主题太多可能造成维护复杂度上升。
- 自定义壁纸可能破坏可读性。
- 二次元和国风装饰可能干扰信息层级。

应对：主题全部走 token；壁纸必须有可读性保护；装饰元素必须可关闭。

### 13.2 产品风险

- 模块太多可能变成臃肿工具。
- 用户首次进入可能选择困难。
- 小程序完整移动版如果照搬桌面端，可能导致移动端操作过重。

应对：首次只问“你主要用来做什么”和“你喜欢什么视觉风格”，其余模块后续逐步推荐。小程序端坚持“核心闭环完整、复杂能力模块化开启”，不把桌面端的长表单、复杂配置和大屏复盘直接搬到移动端。

### 13.3 隐私风险

- 健康、情绪、壁纸、财务和 AI 输入都可能包含敏感信息。

应对：默认本地优先；日志脱敏；同步单独授权；提供删除和导出入口。

### 13.4 医疗风险

- 女性周期模块不能被误解为医疗诊断。

应对：只做记录、预测、提醒和生活建议；异常情况提示就医；明确免责声明。

## 14. 验证标准

### 14.1 视觉验证

- 每个主题正文对比度目标不低于 4.5:1。
- 标题、图标、按钮文字目标不低于 3:1。
- 高饱和强调色面积受控。
- 壁纸开启后文字仍清晰可读。

### 14.2 功能验证

- 不同 Persona 首页结构不同。
- 不同 Feature Module 可独立开启/关闭。
- 小程序端具备首页、计划、快速新增、模块和我的五个主入口。
- 小程序端快速新增可以覆盖任务、灵感、症状、笔记和错题等移动高频输入。
- 女性周期数据不进入普通任务日志。
- 主题切换不影响用户数据。
- 壁纸删除后可恢复默认主题背景。

### 14.3 隐私验证

- 高敏感数据默认本地保存。
- 日志不输出健康、财务、壁纸原图或 AI 隐私输入。
- 删除功能能清除对应模块本地数据。

### 14.4 测试策略

- Theme Profile Registry 测试。
- Wallpaper 配置测试。
- Persona Template 测试。
- Feature Module 开关测试。
- PrivacyLevel 测试。
- 小程序页面结构契约测试。
- 小程序与桌面端共享 WorkspaceState 数据契约测试。
- 女性周期预测基础测试。
- 主界面按 Persona 渲染测试。

## 15. 实施顺序

按单模块串行开发：

1. 主题系统规格化与 8 个主题 token。
2. 壁纸上传与可读性保护配置。
3. WorkspaceState 命名与数据结构兼容演进。
4. Persona 首页差异化结构。
5. 学生/备考模块深化。
6. 职场/办公模块深化。
7. 女性周期/能量管理基础模块。
8. 自律成长低压力模块。
9. 内容创作者模块。
10. 生活管理模块。
11. 小程序完整移动版结构设计。
12. AI 辅助层设计。
13. 多端同步与移动端适配设计。

## 16. 非目标

第一阶段不做：

- 医疗诊断。
- 默认云同步健康数据。
- 真实 AI Provider 接入。
- iOS/HarmonyOS 原生实现。
- 小程序真实发布上线。
- 小程序与桌面端真实云同步。
- 主题市场。
- 社区功能。
- 复杂财务记账。

## 17. 参考资料摘要

- WCAG 与华为 UX 体验规范均强调正文文本与背景对比度建议不低于 4.5:1，标题、图标等不低于 3:1。
- 多巴胺配色资料显示，高饱和配色能提升情绪价值，但长期使用需要控制面积比例，建议采用柔和多巴胺、70/20/10 或类似比例减少视觉疲劳。
- 女性健康类应用普遍强调周期预测、症状记录、情绪/睡眠/运动关联、隐私锁、本地存储和无广告体验。
- 效率工具痛点集中在任务分散、优先级混乱、同步复杂、缺乏专注机制和复盘成本高。
